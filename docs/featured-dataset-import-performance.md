# 精选数据集导入性能基线

**测量日期：** 2026-10-22
**实现：** `dev` 分支任务化导入版本
**环境：** 本机 Python 3.12、SQLite、单 Worker；导入全过程使用本地数据，无 GitHub 请求。

## 结果

| 数据包 | 压缩包体积 | 仓库数 | 记录总数 | 导入耗时 | 进程峰值 RSS | 最大 `BEGIN IMMEDIATE` 等待 | 最大任务状态读取 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 当前精选包 | 3.43 MiB | 15 | 45,011 | 5.20 s | 187.5 MiB | 0.134 ms | 13.428 ms |
| 5 倍合成包 | 18.31 MiB | 75 | 225,055 | 30.04 s | 562.0 MiB | 0.347 ms | 57.530 ms |

两个包均完整导入成功：当前包写入 22,453 条活动事件，5 倍包写入 112,265 条；仓库、快照与任务结果计数一致，warning/skipped 均为 0。

## 测量方法与边界

- 直接运行正式 Worker 导入流程，包含数据包校验、分批暂存、详情归档和最终数据库事务。
- 每个数据包执行一次，使用新建的本地 SQLite 数据库；5 倍包由当前精选包扩展为 5 倍仓库和记录规模，并为仓库生成独立 ID。
- RSS 使用进程峰值常驻内存；状态读取延迟在导入期间每 50 ms 查询一次，锁等待记录 Worker 发起的 `BEGIN IMMEDIATE` 调用耗时。
- 这是单机单次基线，不代表多 Worker、生产数据库或并发负载下的容量上限；重复测量会有文件系统缓存、进程调度和本机负载差异。

## 优化记录

首次 5 倍试跑的峰值 RSS 约 1.4 GiB。原因是 Worker 在暂存完成后仍保留整包解析对象，并把全部 ORM 暂存行和反序列化字典同时载入内存。当前实现释放原始解析对象，按记录类型惰性读取，并通过仓库索引逐仓库加载详情。相同 5 倍包的单次复测峰值 RSS 降至约 562 MiB，导入仍成功。
